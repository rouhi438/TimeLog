# TimeLog CPR security patch (candidate)
Based on TimeLog-current.zip plus TimeLog-Fridag.zip. Replace only the three files in this patch, maintaining other current project files. Review git diff before deploying.

1. Test on a separate database/branch containing synthetic data only. Do not copy production personal data. Generate a unique key locally: `openssl rand -hex 32`. Put it in `.env.local` as `TIMELOG_CPR_KEY` and in the relevant Vercel environment as a sensitive server-only variable. Never use NEXT_PUBLIC_, commit the key, or send it to chat. Keep an access-controlled recovery copy separate from the database. Use different keys for isolated environments.
2. Run `npm ci`, `npx tsc --noEmit`, `npm run build`. No production deployment until tests pass. Existing DB schema unchanged. The first authorized GET migrates existing valid plaintext CPR in a compare-and-swap update; old versions/backups can still contain plaintext. Invalid legacy data fails closed. Do not revert to the old API after migration without a compatible recovery plan.
3. Test with a synthetic employee and dummy identifier `000000-0000` (format test only, not a valid CPR). Confirm ordinary GET/PUT responses contain hasCpr and cprLast4, never the full number or ciphertext. Confirm DB employee cpr begins with v1: and no plaintext number is stored there. Confirm edit without CPR preserves it, replacement works, duplicate is rejected, removal works, concurrent edits yield 409, CSV and JSON backups omit CPR and its last four digits. The existing PDF / Print button fetches full CPR for the employee overview, including employees with zero hours, and renders it only for print; afterprint clears the data. Browser-menu printing without the button does not fetch CPR. Verify cancellation and actual PDF on desktop and Samsung, and treat exported PDFs as confidential. Employee CPR is masked as six dots plus four digits, click toggles, and navigation clears revealed values. Explicit CPR reveal uses a separate POST and manager authorization, not fresh password/MFA. Test unauthenticated and authenticated non-manager GET/PUT/POST all return 403. Check actual response headers, browser storage, logs, old backups, Data API and database privileges. Do not enter CPR into notes or other fields.
4. Restore from downloaded JSON does not import CPR; it preserves existing CPR only for matching employee IDs, and drops records absent from the backup. Database disaster recovery requires protected DB backups and the matching key. Key rotation, fresh reauthentication, audit events, and retention/old backup remediation remain separate tasks. Do not lose or casually change the key.
5. Production requires employer approval, lawful basis under Danish law, processor agreements, retention policy and commercially permitted hosting. Use synthetic data until all checks pass.

Verification in this environment: crypto round-trip, random IV, tampering, employee-ID binding and missing-key failure tested. Full TypeScript/build/integration not verified because the available dependencies lack Neon SDKs. No live systems were accessed or changed.

Revision 2: syntax/type check attempted; actual browser printing and live integration still require testing. Full numbers are present temporarily in browser memory and the print DOM when requested. No fresh password check or audit log is implemented.
